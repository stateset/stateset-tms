# Canonical block storage integration

`freight_workspaces.data` contains only the versioned codec header, root manifest and original scalar descriptors. Collection records live exclusively in `freight_workspace_blocks`. The complete source is reconstructed from those originals; there is no second writable aggregate. `freight_block_counts` is rebuildable membership metadata used to refuse missing data during selected receipt/history access. Blocks use the qualified 64-record/64-KiB layout, with oversized originals retained.

Migration 026 holds the existing format fence before tenant/table locks, creates the new relations, and runs native lossless backfill between its two SQL halves. It validates the exact original marker and preserves every business root, including unreadable future/unknown data. API reads and mutations still refuse unsupported business data. Header replacement, original blocks, guards, counters and the checksummed migration ledger commit together. Backfill preserves timestamps, portable revisions and original files; only the business-format marker changes.

Native reads fetch the header and block rows at one repeatable-read snapshot. The admitted blocking worker owns the transaction through complete codec and typed decoding. Mutations lock the tenant, validate the complete source, run existing business checks, and prepare actual changed/deleted blocks. Original file validation and source/receipt/file persistence remain in the same transaction. Queued CPU work retains its real connection through caller cancellation and never commits independently.

Persistence compares the original raw source, its typed view before mutation, and the typed result afterward. Unchanged raw values survive timestamp/default normalization, opaque-number rounding and ignored nested fields. Moved unchanged records retain original payloads without deduplicating repeated business IDs. Existing receipts cannot be changed or removed. SHA-256 hashes of fully validated canonical blocks select physical deltas; hashes do not replace complete source/partition validation. Quarantined operations evidence uses raw JSON, with literal map serialization so private-looking keys remain data.

Catalog, history, tender deadlines and queue wakeups read selected canonical roots. History pages and exact receipt lookups select the corresponding ordinal/key bucket. Membership counters, physical changes, derived invalidation and conservative wakeups commit together. The read-only `freight_workspace_originals(tenant)` function supports independent diagnosis/verification; application snapshot reads use the native codec.

Qualification passes 272 active Rust/component tests, 70 PostgreSQL 16 scenarios, 26 Node tests, eight actual captured EDI codec checks and all 100 production-browser scenarios without retries, failures or skips. Formatting, workspace Clippy and the optimized host build pass. The browser suite uses an owned memory-mode API with unchanged production Next.js assets; durable behavior is checked separately. The exact Docker COPY source closure includes the codec workspace, but a container image build was not performed.

Three native [migration/delta scenarios](../tests/canonical_blocks.rs) cover concurrent startup, exact JSONB reconstruction and decimal scale, opaque policy/case/receipt retention, original file bytes, obsolete and forged-current aggregate-writer refusal, unrelated physical tuples, tenant isolation, original retries and atomic rollback after a later tenant refuses backfill. Absent optional inbox/history collections retain empty defaults through unrelated writes; explicit nulls and missing declared originals are refused. Unchanged defaults also remain absent in nested raw data. Selected history preserves the actual future marker and returns the compatibility error rather than hiding it as a generic storage failure.
